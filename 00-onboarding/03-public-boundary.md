# 公开边界：什么能写、什么不能写

> ⚠️ **这是本仓库最重要的治理文件。所有 Agent 在产出任何公开内容前，必须先读完本文件。**
>
> **V0.1 骨架版**：边界定义待 Randy 逐条确认。当前内容基于大榕和 FDE 对 Randy 体系的已知理解拟定，标注「待确认」的条目需 Randy 签字。

---

## 一、总原则

本仓库（Randy-AI-knowledge-base / Randy-AI认知库）是 Randy 的**公开 AI 认知库**。它与 Randy 的私有 Obsidian Vault 的关系是：

| 维度 | Obsidian Vault（私有） | Randy-AI-knowledge-base GitHub（公开） |
|------|----------------------|------------------------|
| 读者 | 4 个 Agent + Randy 本人 | 未来的 Agent、协作者、公众 |
| 内容层级 | 全部工作产物、日志、思考草稿 | 方法论、框架、模板、认知输出 |
| 内容状态 | 随时读写、草稿态 | 经过筛选、可公开的成品 |
| 隐私要求 | 包含客户、业务、私人数据 | 完全脱敏，不含任何业务隐私 |

## 二、绝对不能写的内容（红线）

以下任何一项出现在公开仓库中，即为严重违规：

### 业务隐私
- ❌ 客户公司名、真实业务数据、营收数字
- ❌ 合作方联系人、合同条款、报价
- ❌ 未公开的产品路线图、商业计划书内容

### 个人隐私
- ❌ Randy 的家庭信息、住址、个人联系方式
- ❌ Randy 的财务信息、投资记录
- ❌ Randy 未主动公开的个人经历细节

### 技术安全
- ❌ API 密钥、Token、密码
- ❌ 内部服务的 IP、域名、端口
- ❌ 安全漏洞、未修复的系统弱点

## 三、需要 Randy 逐条确认才能写的内容（黄线）

以下内容**可以出现在公开仓库**，但必须满足条件：

### 可以写，但必须先过 Randy 确认
- ⚠️ Randy 的个人信念、价值观表述（见 `01-randy-profile.md`）→ **需 Randy 逐条确认**
- ⚠️ 真实项目案例（如 xiaofen.ai、TIMEABLE）→ **只写已公开的信息，不写内部数据**
- ⚠️ Agent 体系的内部架构细节 → **只写方法论层面，不写具体配置**
- ⚠️ 引用 Randy 原话 → **只引用 Randy 已在公开场合说过的话**

### 写法要求
- 引用来源必须标注（如「来自 Randy 的公开分享」「来自 Obsidian Vault，经 Randy 确认公开」）
- 不确定的内容标注「待 Randy 确认」
- 案例只写故事和方法，不写具体公司内部数据

## 四、可以自由写的内容（绿线）

以下内容 Agent 可以自主判断产出，无需逐条等确认：

- ✅ 纯方法论、框架、思维模型（基于 Randy 体系的提炼）
- ✅ 模板、提示词、工作流（可复用的工程资产）
- ✅ Agent 角色定义、协作流程、考核标准
- ✅ 仓库自身的维护文档、路线图
- ✅ 目录导航、README、使用说明

## 五、Agent 产出检查清单

每次在公开仓库创建或更新文件前，自查以下 5 条：

- [ ] 是否包含客户/公司/个人隐私数据？
- [ ] 是否包含 API 密钥、Token、密码？
- [ ] 是否引用了 Randy 未公开说过的话？
- [ ] 案例描述是否脱敏？（不写具体公司名/数据）
- [ ] 不确定的内容是否标注了「待 Randy 确认」？

**任何一条打 ❌，先暂停，标注「需要 Randy 确认」。**

## 六、违规处理

如果 Agent 在公开仓库产出了违规内容：

1. 立即删除该内容
2. 在 `90-meta/` 中记录违规类型和原因
3. 更新本文件，补充遗漏的边界规则
4. 发 PR 说明修复了什么、为什么违规
